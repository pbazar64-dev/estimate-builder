# 08. Безопасность

## 8.1. Аутентификация
- **OAuth 2.0** приложения Битрикс24 (server-side flow). Пользователь входит из
  портала; приложение получает код → обменивает на `access/refresh token`,
  проверяет `member_id` (домен портала) и `user_id`.
- На основе B24-пользователя выпускается **сессия приложения (JWT)**, хранящая
  `userId`, `role`, `memberId`, срок жизни; refresh — по ротации.
- Токены Битрикс24 хранятся на бэкенде (не в браузере), шифруются at-rest.

## 8.2. Авторизация (RBAC) на уровне API
- Каждый endpoint защищён guard'ом: проверка роли + владения ресурсом.
- **Deny by default**; аналитик — глобальный запрет мутирующих методов.
- Проверка соответствия `memberId` (изоляция между порталами/тенантами).
- Права не доверяются клиенту — UI лишь отражает то, что разрешит бэкенд.

## 8.3. Защита веб-слоя
- **CSRF:** для cookie-сессий — `SameSite=Lax/Strict` + анти-CSRF токен; для
  Bearer-JWT в заголовке — CSRF неактуален. Встраивание в iframe портала —
  строгий `frame-ancestors` (только домены Битрикс24) в CSP.
- **XSS:** экранирование, React-автоэкранирование, `Content-Security-Policy`,
  запрет `dangerouslySetInnerHTML` кроме проверенного рендера; санитизация
  пользовательских описаний в документах.
- **Инъекции:** параметризованные запросы/ORM, валидация DTO (class-validator).
- **CORS:** whitelist доменов портала.
- **Rate limiting** и защита от перебора на auth/generation endpoints.
- **Загрузка шаблонов:** проверка типа/размера, антивирус-скан, изоляция
  рендера документов (docxtemplater в песочнице, ограничение выражений).

## 8.4. Данные
- TLS для всего трафика; шифрование чувствительных полей at-rest.
- Разделение секретов (vault/env), ротация ключей.
- Бэкапы PostgreSQL (PITR); документы — версионируемое объектное хранилище.
- Соответствие требованиям по локализации данных для юрлиц РФ/РБ/КЗ/PL
  (размещение стенда согласуется с заказчиком).

## 8.5. Логирование и аудит
- **Аудит бизнес-действий** (`audit_log`): создание/изменение/удаление смет,
  сохранение версий, откаты, решения согласования, генерация документов,
  изменение настроек — с `actor, entity, diff, ip, timestamp`.
- **Технические логи**: структурные (JSON), корреляция по `requestId`, без PII
  в логах.
- Хранение аудита — неизменяемое (append-only), доступ на чтение — рук. компании
  и аналитику.
- Мониторинг/алерты: ошибки генерации, недоступность Битрикс24 API, деградация.
