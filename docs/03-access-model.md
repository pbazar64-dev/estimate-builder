# 03. Модель доступа (ролевая модель)

Роли синхронизируются с оргструктурой Битрикс24 (отделы/должности) + явное
назначение в настройках модуля. Проверка прав — **на уровне API** (backend),
UI лишь скрывает недоступные действия.

## Матрица прав

| Действие | Рук. компании | Рук. проектов | Менеджер продаж | Бизнес-аналитик |
|---|:---:|:---:|:---:|:---:|
| Просмотр всех смет | ✅ | ✅ | ✅ | ✅ (read-only) |
| Просмотр всех версий | ✅ | ✅ | ✅ | ✅ |
| Создание сметы | ✅ | ✅ | ✅ | ❌ |
| Редактирование сметы | ✅ | ✅ | ✅ | ❌ |
| Удаление сметы | ✅ | ❌¹ | ❌ | ❌ |
| Управление версиями (откат) | ✅ | ✅ | ✅ | ❌ |
| Запуск согласования | ✅ | ✅ | ✅ | ❌ |
| Принятие решения в согласовании | ✅ | ✅² | ✅² | ❌ |
| Генерация КП | ✅ | ✅ | ✅ | ❌ |
| Генерация договора/спецификации | ✅ | ✅ | ✅ | ❌ |
| Просмотр истории изменений | ✅ | ✅ | ✅ | ✅ |
| Просмотр КП/договоров | ✅ | ✅ | ✅ | ✅ |
| Просмотр аналитики | ✅ | ✅ | ✅ | ✅ |
| Управление каталогом типовых работ | ✅ | ✅ | ❌ | ❌ |
| Управление настройками системы | ✅ | ❌ | ❌ | ❌ |

¹ Удаление — только Руководитель компании (мягкое удаление/архив, не физическое).
² Только если роль включена в маршрут согласования конкретной сметы.

## Принципы

1. **Deny by default** — любое действие без явного разрешения запрещено.
2. **Проверка на бэкенде** — каждый API-метод валидирует роль и владение.
3. **Read-only для аналитика** — на уровне middleware блокируются все
   мутирующие методы (POST/PUT/PATCH/DELETE), включая генерацию.
4. **Аудит** — все действия логируются (кто/что/когда), см. `docs/08-security.md`.
5. **Наследование из Битрикс24** — маппинг «должность/отдел → роль модуля»
   настраивается администратором; по умолчанию — минимальные права.

## Роли (сводно)

- **Руководитель компании** — суперпользователь + настройки системы.
- **Руководитель проектов** — полный операционный доступ, каталог, без настроек.
- **Менеджер по продажам** — полный доступ к сметам/генерации, без каталога и настроек.
- **Бизнес-аналитик** — только чтение всего, без единого мутирующего действия.
