# 00. Разбор исходных документов «Ава Тетис»

Всё ТЗ опирается на три реальных документа компании. Здесь зафиксировано, что
именно из них извлечено и как это отражается в модуле.

---

## 1. Смета (Excel) — ядро системы

Файл содержит **4 листа**, которые в модуле превращаются в **сценарии/наборы
этапов одной сметы**:

| Лист | Роль в модуле |
|---|---|
| `Расчёты ППИ` | Этап «Предпроектное исследование» (по умолчанию выключен) |
| `Расчёты (без разработки)` | Базовый сценарий: Моделирование + Настройка штатного функционала + Введение в ОПЭ |
| `Расчёты (с разработкой)` | Тот же набор + этап «Разработка» |
| `Для КП` | Клиентское представление сметы (урезанные колонки) для генерации КП |

### 1.1. Таблица ставок (шапка листа)

```
                         Бел.руб   Рос.руб   Тенге    Злотый
Ставка часа              80        3000      15000    200
Валюта расчёта           Злотый (выбирается пользователем)
```

→ В модуле это справочник **«Страны и ставки»** (см. `docs/06-data-model.md`,
сущность `Country`) + поле «Валюта расчёта» на смете. Ставка часа **фиксируется
в версии** (снапшот), чтобы пересчёт задним числом не «поехал».

### 1.2. Колонки таблицы сметы

| # | Колонка | Назначение |
|---|---|---|
| 1 | `№` уровень 1 | Номер этапа (1, 2, 3) |
| 2 | `№` уровень 2 | Номер группы (1.1, 2.3) |
| 3 | `№` уровень 3 | Номер услуги (2.3.1) |
| 4 | `Наименование` | Название этапа/группы/услуги |
| 5 | `Описание задачи` | Текстовое описание (шаблонное) |
| 6 | `Количество` | Кол-во единиц |
| 7 | `Трудозатраты Исполнителя` (ч) | Внутренние плановые часы (загрузка ресурсов) |
| 8 | `Трудозатраты Клиенту` (ч) | Часы, по которым считается цена клиенту |
| 9 | `Стоимость` | Итоговая стоимость строки |

### 1.3. Формулы (проверены на данных листа «без разработки»)

```
Стоимость строки = Ставка часа × Трудозатраты Клиенту × Количество
```

Проверка:
- R7 «Онлайн интервью»: 200 × 1 × 3 = **600** ✔
- R9 «Написание ТЗ»: 200 × 16 × 1 = **3200** ✔
- R39 «Открытая линия + ТП»: 200 × 5 × 1 = **1000** ✔

Итоги по этапам и общий ИТОГО — суммы стоимостей (Моделирование 4400,
Настройка 10600, ОПЭ 4400, ИТОГО **19400** злотых; часы исполнителя 68,
клиенту 95).

### 1.4. Дополнительные блоки (входят в модуль)

- **Срок реализации**: дни / недели / месяцы (в примере 48 дней ≈ 10 недель ≈ 2.5 мес).
  → вычисляемое поле сметы (алгоритм — из суммарных трудозатрат, коэффициент настраивается).
- **Платёжный календарь** (прогнозный): 3 платежа — Аванс, Доплата за этап 2,
  Предоплата за этап 3, с суммами, сроками («N рабочих дней с предыдущей оплаты»)
  и предварительными датами. → блок «График платежей» в карточке сметы и в
  генерируемых документах.

### 1.5. Трёхуровневая иерархия — подтверждена

Пример из листа:
```
1     Моделирование                       (этап)
  1.1 Онлайн интервью                      (услуга напрямую под этапом)
2     Настройка штатного функционала       (этап)
  2.3 СРМ                                  (группа)
    2.3.1 Настройка пользовательских полей (услуга)
```

Вывод: уровень 2 может быть **как группой, так и услугой** (гибкая
вложенность). Редактор должен поддерживать повышение/понижение уровня строки.

## 2. Коммерческое предложение (PDF) — «АО Конаково»

**7 страниц**, структура (→ шаблон КП в модуле):

1. **Обложка**: «КОММЕРЧЕСКОЕ ПРЕДЛОЖЕНИЕ НА ВНЕДРЕНИЕ БИТРИКС24 ДЛЯ {КЛИЕНТ}»,
   `ДАТА`, `ДЕЙСТВИТЕЛЬНО ДО` (+14 дней).
2. **Предварительные блоки/позиции** (лицензия, разворот коробки, настройка) —
   с ценой и сроком. → опциональные «внешние позиции» поверх сметы.
3. **Разбивка по этапам** — таблица `№ / Наименование / Описание / Количество /
   Стоимость`. **Часы клиенту не показываются** — только стоимость (это и есть
   лист «Для КП»).
4. **Условия оплаты** (предоплата 50%, поэтапная оплата) + **Срок реализации**.
5. **«О компании»** — маркетинговый текст (константа шаблона).
6. **«Наши клиенты»** — логотипы (ассеты шаблона).
7. **«Контакты»** — менеджер + реквизиты по 4 странам (РФ, РБ, Казахстан, Польша).

→ КП генерируется из **выбранной версии сметы**: подставляются клиент, этапы,
стоимости, срок, условия оплаты; статичные блоки берутся из шаблона.

## 3. Договор / Спецификация (DOCX) — № VB24-289

Документ — **«Приложение № 9 / Спецификация № 9»**, которая «одновременно
является протоколом согласования цен». Структура (→ шаблон спецификации/договора):

- **Шапка**: № договора, № спецификации, город, дата.
- **Основные положения / Сроки** (N рабочих дней с предоплаты).
- **Стоимость** — общая + разбивка по 3 этапам (Моделирование 36 000,
  Настройка 75 000, ОПЭ 21 000; ИТОГО 132 000 ₽ без НДС гл.26.2 НК РФ).
- **Ответственное лицо со стороны Заказчика** (ФИО).
- **Перечень услуг** — таблица `№ / Этап-Задача (3 уровня) / Описание / Кол-во /
  Стоимость` (та же смета, клиентское представление).
- **Порядок расчётов**: аванс 50%, поэтапная 100% предоплата, критическое условие.
- **План-график платежей** — таблица `№ / Наименование / Сумма / Срок /
  Ориентировочная дата / Документы (Акт)`.
- **Реквизиты и подписи сторон** (Исполнитель ООО «Ава Тетис» + Заказчик).

→ Договор/спецификация генерируется из версии сметы: подставляются реквизиты
сторон (из CRM), стоимость по этапам, перечень услуг, план-график платежей.

## 4. Выводы для проектирования

1. **Одна смета — три представления**: внутреннее (с часами исполнителя),
   клиентское «Для КП» (без часов), договорное (перечень услуг + этапы).
   Генераторы КП/договора берут одни и те же данные версии.
2. **Ставка и валюта — атрибут версии** (снапшот), а не только справочника.
3. **Этапы — конфигурируемый набор** с флагом «активен по умолчанию»
   (ППИ и Разработка выключены по умолчанию).
4. **Платёжный календарь** — часть доменной модели, а не только текст в документе.
5. **Трудозатраты Исполнителя** сохраняются как внутренние плановые часы
   (планирование загрузки), но расчёт маржинальности не ведётся.
6. **Мультивалютность/мультистрановость** — обязательна с первого дня
   (у компании юрлица в РФ, РБ, Казахстане, Польше).
