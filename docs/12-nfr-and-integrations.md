# 12. Нефункциональные требования, производительность, масштабируемость, интеграции

## 12.1. Производительность

**Редактор больших смет (1000+ строк):**
- Виртуализация таблицы (рендер только видимых строк).
- Дебаунс пересчёта; инкрементальный пересчёт затронутого поддерева, а не всей
  сметы.
- Клиентский CalcEngine для мгновенного UX; серверный — источник истины
  (сверка при сохранении версии).

**Кэширование:**
- Redis-кэш данных CRM (сделка/компания/контакт/реквизиты) с TTL и инвалидацией
  по вебхукам `ONCRMDEALUPDATE`.
- Кэш каталога и справочников (страны/этапы) — редко меняются.
- HTTP-кэш статики SPA (CDN, хэш-имена).
- Кэш агрегатов аналитики (материализованные представления/периодический
  пересчёт).

**Фоновая обработка:**
- Генерация DOCX/PDF/Excel — в очереди (BullMQ), не блокирует UI; статус задачи
  опрашивается/пушится.

**Целевые показатели:**
- Открытие реестра < 1с; открытие сметы < 1.5с; пересчёт строки < 100мс;
  генерация документа < 10с (асинхронно).

## 12.2. Индексы БД
См. `docs/06-data-model.md` §6.4 (btree по фильтрам реестра, GIN trigram для

## 12.3. Масштабируемость и отказоустойчивость

**Рост объёма смет:**
- Stateless API → горизонтальное масштабирование (N реплик за балансировщиком).
- Партиционирование `estimate_version`/`audit_log` по дате при большом объёме.
- Архивные сметы — отдельная «холодная» выборка, не мешают активным индексам.

**Отказоустойчивость:**
- PostgreSQL с репликой (read-replica для аналитики) + PITR-бэкапы.
- Redis — для кэша/очередей; потеря кэша не критична (пересбор из БД/CRM).
- Graceful degradation при недоступности Битрикс24 API: работа с кэшем CRM-данных,
  отложенная синхронизация.
- Идемпотентность генерации и записи версий.
- Мониторинг/алерты (ошибки, латентность, доступность B24 API).

## 12.4. Интеграции

**Текущие (в составе продукта):**
- Битрикс24 REST/вебхуки/OAuth/placement (CRM, задачи, уведомления, встраивание).

**Будущие:**
- **1С** (после MVP/Prod): выгрузка утверждённых смет/договоров, синхронизация
  сумм и этапов; через промежуточный обмен (файлы/REST) с маппингом номенклатуры.
- **Внешние CRM/ERP:** исходящие вебхуки (`estimate.approved`, `estimate.signed`,
  `document.generated`) с HMAC-подписью; конфигурируемые endpoints.
- **Задел под маркетплейс Битрикс24:** упаковка приложения для дистрибуции.

## 12.5. Прочие NFR
- **Локализация:** RU (основной), мультивалютность/мультистрановость (РФ/РБ/КЗ/PL/…).
- **Доступность:** десктоп-first; корректная деградация на планшете.
- **Совместимость:** современные Chromium/Firefox (внутри iframe портала).
- **Наблюдаемость:** структурные логи, requestId-корреляция, дашборды состояния.
- **Соответствие данным:** размещение стенда с учётом требований юрлиц компании.
